# Prisma 8 database schema — manual release gate

`src/prisma/contract.prisma` defines a **non-null**
`VehicleType.driverBattaPerDayLkr Int @default(0)` column. At audited commit
`2fb6463`, the dated migration directories do **not** add this field. A database
at the old marker can throw `column vehicleType.driverBattaPerDayLkr does not exist`.

**Do not run migration commands against production until staging succeeds.**

1. Confirm the actual database **using a read-only account** (or approved DB console):

   ```sql
   SELECT column_name, data_type, is_nullable, column_default
   FROM information_schema.columns
   WHERE table_schema = 'public' AND table_name = 'vehicleType'
     AND column_name = 'driverBattaPerDayLkr';
   ```

   Zero rows means the physical column is missing. A column being present does
   **not** prove that the Prisma migration marker and generated contract agree.

2. Take a tested database backup / recovery point, clone a **staging database**.
   Using the **project's pinned Prisma 8 release-candidate CLI**, run:

   ```bash
   npm ci
   npm run contract:emit
   npx prisma migration plan --name add_driver_batta
   npx prisma db migrate --show
   ```

   Review the proposed migrations/ops and contract marker. The intended change
   is an integer `driverBattaPerDayLkr NOT NULL DEFAULT 0` on `vehicleType`.
   **Stop** if the tool wants to remove/recreate tables or change unrelated fields.
3. Apply the approved plan to staging; run `npm run db:verify`, `npm run db:check`,
   build and booking integration tests. Commit the CLI-generated migration files,
   snapshots, contract artifacts and updated refs **as a separate reviewed PR**.
4. After backup and rollout approval, deploy that reviewed schema change to
   production, check admin Vehicles reads/writes, configure positive daily driver
   rates for active vehicles, then release the code.

**Important:** No handcrafted Prisma migration is included in these patches:
Prisma's migration hashes and snapshot contracts must be generated by its
pinned CLI against the intended actual database state, not invented offline.
Do not use `ALTER TABLE` alone as a substitute for tracking the Prisma marker.
